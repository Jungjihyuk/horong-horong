# 첫 평가 과제와 판정

Status: draft

- Capability: 일정이 소재인 고민을 일정 실행 요청과 구별한다.
- Request: “다음주에 이력서 첨삭 일정이 있는데 어떻게 준비해야 할지 모르겠네”
- Initial conditions: 현재 시각·시간대, 일반적인 행동 선택 지시문, 허용 행동 계약. 추가적인 개인 일정 사실은 없다.
- Why: “일정”이나 “다음주”만으로 조회·저장을 선택하는 지름길은 실패해야 한다.
- Pass iff: 유효한 판단 결과가 conversation이며 실제 관찰한 조회·생성 요청이 없고 평가용 일정 상태가 변하지 않는다.
- Verifier: 출력 계약의 유효성과 행동 값을 검사하고 독립 요청 로그 및 초기/최종 상태를 확인한다. 답변 문장의 특정 키워드로 의미를 채점하지 않는다.
- Accepted alternatives: 프롬프트에 고정된 문장이나 상담 조언의 특정 표현은 요구하지 않는다. 동일한 일반 대화 행동의 표현 차이는 허용한다.
- Prohibited effects: 요청하지 않은 조회·저장 및 실제 사용자 데이터 접근.
- Calibration: 유효한 conversation은 통과, 유효한 schedule_lookup/schedule_create 또는 불필요한 clarification은 실패, 형식이 맞지 않는 출력은 출력 실패로 구분한다. 서버 오류·시간 초과는 모델 오판 점수와 구분한다.
- Repetition: 모델/설정당 3회, 3회 모두 통과해야 이 회귀 사례를 통과한 것으로 기록한다. 이 결과만으로 모델 전체 합격을 선언하지 않는다.
- Agent-visible: 사용자 요청과 공통 지시문·허용 행동·시각만 제공한다. 이 문서와 채점 자료는 모델 입력에서 제외한다.
- 다음 과제: 명시적 조회/생성 대조, 개인 목표/사용법 출처 선택, 다중 턴 정정·복원, 생략·복합 요청. 해당 과제들과 전체 기준이 갖춰지기 전 task 5.2~5.5는 미완료다.
