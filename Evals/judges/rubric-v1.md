# 목표 추천 LLM-as-a-Judge 루브릭 v1

## 목적

결정적 지표가 측정하는 **어떤 항목을 연결·안내했는가**와 별개로, 생성된 목표 제목·안내 문장이 의미적으로 타당하고 읽기 좋은지를 평가한다.

이 루브릭은 `Evals/results/*.jsonl`의 실행 결과를 입력으로 받아 Codex CLI, Claude CLI 또는 API judge가 같은 기준으로 평가할 때 사용한다.

## 평가 단위

- `general`, `context_dependent`: 모델이 생성한 목표 그룹 하나와 그 목표 제목 하나
- `insufficient_information`: 모델이 안내한 입력 하나와 그 `suggestion` 문장 하나
- `non_goal_or_noise`: 모델이 안내한 입력 하나와 그 `suggestion` 문장 하나 (왜 목표가 아닌지의 설명 적합성). 모델이 아무 제안 없이 종료(`noSuggestion`)한 경우 생성물이 없으므로 안내 품질 항목은 `N/A`로 둔다.
- 케이스에 그룹 또는 안내 항목이 여러 개면 각각 평가한 뒤 케이스 평균을 낸다.
- 그룹이나 안내가 생성되지 않은 경우 해당 품질 항목은 `N/A`로 둔다. 억지로 0점을 주지 않는다.

## 공통 점수 척도

모든 적용 가능한 항목은 0~5점 정수로 평가한다.

| 점수 | 의미 |
| --- | --- |
| 0 | 기준을 충족하지 못하며 결과를 사용할 수 없음 |
| 1 | 기준을 아주 조금만 충족하거나 중대한 문제가 있음 |
| 2 | 일부 장점은 있으나 핵심 문제가 남아 있음 |
| 3 | 기본적으로 기준을 충족함 |
| 4 | 매우 양호하며 사소한 개선점만 있음 |
| 5 | 기준을 명확하고 완전하게 충족하는 모범적인 결과 |

점수만 반환하지 말고, 판단 근거를 한 문장으로 함께 반환한다.

## A. 군집화 타당성

`general`, `context_dependent`의 생성된 목표 그룹 단위로 평가한다.

### A1. 의미적 응집성 (`semantic_cohesion`)

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 서로 무관한 항목을 묶음 |
| 1 | 단어·도구·앱 이름만 비슷함 |
| 2 | 같은 넓은 분야지만 공통 목적이 약함 |
| 3 | 같은 맥락에 속하지만 하나의 목표로 묶는 근거가 다소 약함 |
| 4 | 공통 목적과 결과가 분명함 |
| 5 | 모든 항목이 하나의 맥락·목적·결과로 자연스럽게 연결됨 |

### A2. 노이즈 배제 (`noise_exclusion`)

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 이질적인 항목이 여러 개 포함됨 |
| 1 | 핵심 그룹과 무관한 항목이 포함됨 |
| 2 | 일부 항목이 경계선상에 있음 |
| 3 | 대체로 적절하지만 한 항목의 관련성이 약함 |
| 4 | 모든 항목이 그룹 목적에 부합함 |
| 5 | 모든 항목이 관련되고, 유사해 보이는 노이즈까지 정확히 배제함 |

`FP`, 함정 위반과 중복될 수 있으므로 결정적 지표를 대체하지 않고 의미적 보조 판정으로 사용한다.

### A3. 누락 최소화 (`omission_minimization`)

기본 판정은 `pairF1`, `recall`, `FN`으로 한다. LLM judge는 사람이 보기에 같은 속성인데 빠진 항목이 있는지 설명하는 보조 판정으로만 사용한다.

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 같은 속성의 핵심 항목을 대부분 빠뜨림 |
| 1 | 연결되어야 할 항목을 여러 개 빠뜨림 |
| 2 | 일부 항목만 포함하고 그룹의 범위가 불완전함 |
| 3 | 핵심 항목은 포함했으나 경계선상 항목이 빠짐 |
| 4 | 연결되어야 할 항목을 거의 빠짐없이 포함함 |
| 5 | 동일한 맥락의 항목을 빠짐없이 포함하고 제외 근거도 타당함 |

### A4. 과잉 묶기 배제 (`overgrouping_avoidance`)

기본 판정은 `FP`, 함정 회피율, `inventedPairs`로 한다. LLM judge는 알려진 함정 외의 의미적 과잉 연결을 보조 판정한다.

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 묶을 근거가 없는데 억지로 하나의 목표로 묶음 |
| 1 | 핵심 근거가 약한 항목을 여러 개 포함함 |
| 2 | 관련성은 일부 있으나 분리하는 편이 자연스러운 항목이 있음 |
| 3 | 대체로 적절하나 경계선상 항목을 포함함 |
| 4 | 필요한 항목만 연결하고 무관한 항목은 제외함 |
| 5 | 연결 여부의 경계를 정확히 판단하고 과잉 제안을 피함 |

## B. 목표 구체성 및 실행성

생성된 목표 제목 또는 설명 단위로 평가한다.

### B1. 측정 가능성 (`measurability`)

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 측정 기준이 전혀 없음 |
| 1 | “잘하기”, “개선하기”처럼 추상적인 의도만 있음 |
| 2 | 대상은 있으나 수량·기준이 없음 |
| 3 | 수량이나 완료 기준 중 하나가 있음 |
| 4 | 대상, 수량, 완료 기준이 대부분 명확함 |
| 5 | 대상·수치·범위·완료 조건이 모두 명확해 달성 여부를 바로 판단할 수 있음 |

### B2. 명확성 (`clarity`)

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 의미를 이해하기 어려움 |
| 1 | 여러 해석이 가능함 |
| 2 | 핵심 의도는 보이나 대상이나 결과가 모호함 |
| 3 | 기본 의미는 명확하지만 일부 정보가 생략됨 |
| 4 | 대상·행동·결과를 추가 설명 없이 이해할 수 있음 |
| 5 | 짧고 구체적이며 누구나 동일하게 해석함 |

### B3. 실행 가능성 (`feasibility`)

현재 사용자 역량·시간·상태 데이터가 부족하므로 v1에서는 `N/A`로 평가한다.

### B4. 관련성 (`relevance`)

등록된 페르소나 또는 비전이 있을 때만 평가한다. 없으면 `N/A`다.

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 비전과 반대되거나 무관함 |
| 1 | 표면적으로만 관련됨 |
| 2 | 관련 분야지만 연결 이유가 약함 |
| 3 | 비전과 어느 정도 연결됨 |
| 4 | 비전을 직접 지원함 |
| 5 | 비전과 우선순위까지 정확히 반영한 핵심 목표임 |

### B5. 시간 적합성 (`time_fit`)

기간·기한의 사실 여부는 결정적 검사로 확인하고, LLM judge는 목표 범위와 기간의 적합성을 평가한다.

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 기간 안에 달성할 수 없거나 시간 조건이 목표와 모순됨 |
| 1 | 기간이 지나치게 비현실적임 |
| 2 | 가능성은 있으나 목표 범위와 기간의 균형이 약함 |
| 3 | 주어진 기간 안에 대체로 가능한 범위임 |
| 4 | 목표 범위와 기간이 잘 맞음 |
| 5 | 기간·단계·완료 기준이 서로 정교하게 맞물림 |

## C. 자연어 품질

목표 제목 또는 안내 문장 단위로 평가한다.

### C1. 문법 (`grammar`)

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 문법 오류로 의미를 이해하기 어려움 |
| 1 | 오류가 반복되어 읽기 어려움 |
| 2 | 오류가 눈에 띄지만 의미는 이해됨 |
| 3 | 사소한 오류만 있음 |
| 4 | 문법적으로 거의 완벽함 |
| 5 | 문법적으로 정확하고 자연스러움 |

### C2. 어휘 (`vocabulary`)

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 잘못된 단어로 의미가 바뀜 |
| 1 | 부적절하거나 혼란스러운 표현이 많음 |
| 2 | 의미는 전달되지만 어색하거나 지나치게 일반적임 |
| 3 | 대부분 적절하나 일부 표현이 모호함 |
| 4 | 대상과 맥락에 맞는 정확한 어휘를 사용함 |
| 5 | 정확하고 자연스러우며 불필요한 전문용어가 없음 |

### C3. 목표·안내 어투 (`tone`)

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 목표·안내 문장이 아니거나 의미를 전달하지 못함 |
| 1 | 대화체·감탄체 등 부적절한 표현이 많음 |
| 2 | 목표 의도는 있으나 구어적·소극적 표현이 섞임 |
| 3 | 기본적인 목표·안내 문장 형태를 갖춤 |
| 4 | 행동과 결과가 드러나는 일관된 어투임 |
| 5 | 간결하고 능동적이며 실행 가능한 문장으로 완성됨 |

## D. 안내 품질 (정보 부족 및 비목표 안내)

`insufficient_information` 및 `non_goal_or_noise`의 안내 항목 단위로 평가한다. `guidanceF1`은 안내 대상 ID를, `missingF1`은 보완 기준을, `noSuggestionCorrect`는 비목표 침묵/전체 안내 여부를 결정적으로 평가하므로 이 영역은 **안내 문장이 실제로 입력을 유용하게 구체화하거나 왜 목표가 아닌지 타당하게 설명하는지**의 의미 품질만 본다.

### D1. 안내 적합성 (`guidance_fit`)

- `insufficient_information`: 입력의 원래 의도를 해치지 않으면서 누락된 기준(`missing`)을 보완하도록 적절히 안내했는지 평가한다.
- `non_goal_or_noise`: 골든셋의 비목표 판정 이유(`classification`, `reason`)에 비추어, 해당 입력이 왜 목표로 적합하지 않은지(상태/감정 기록, 링크, 단순 메모, 모호한 생각 등)를 적합하고 명확하게 설명했는지 평가한다.

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 원래 입력/비목표 판정과 무관하거나 정반대인 안내·설명 (예: 비목표를 목표로 삼으라고 유도) |
| 1 | 관련 영역만 피상적으로 반복하거나 왜 목표가 아닌지 알 수 없음 |
| 2 | 누락 기준이나 비목표 이유 중 일부만 다루거나 핵심에서 다소 벗어남 |
| 3 | 주요 누락 기준이나 비목표 이유를 대체로 다루지만 표현이 일반적임 |
| 4 | 누락 기준이나 비목표 이유(분류 및 사유)를 정확히 반영하고 의도를 유지함 |
| 5 | 누락 기준을 명시적으로 보완하거나 비목표인 이유를 명확·자연스럽고 완벽하게 설명함 |

### D2. 안내 실행성 (`guidance_actionability`)

`insufficient_information`의 안내 항목에 대해서만 평가한다. `non_goal_or_noise`는 비목표 입력이므로 사용자가 구체화할 실행 행동을 요구하지 않아 `N/A`로 둔다.

| 점수 | 판정 기준 |
| --- | --- |
| 0 | 실행할 수 있는 안내가 아님 |
| 1 | 추상적인 조언만 제공함 |
| 2 | 방향은 있으나 사용자가 무엇을 정할지 불분명함 |
| 3 | 다음 행동의 방향이 보임 |
| 4 | 사용자가 바로 수정할 대상과 기준을 알 수 있음 |
| 5 | 원래 내용을 보존하면서 구체적이고 현실적인 다음 행동을 제시함 |

## 집계 규칙

- `N/A` 항목은 평균의 분모에서 제외한다.
- 먼저 케이스 내부 항목의 평균을 내고, 그 다음 모델별 케이스 평균을 낸다.
- 영역별 점수(`clusteringValidity`, `goalSpecificity`, `languageQuality`)를 먼저 계산한다.
- 결정적 지표와 LLM judge 점수는 하나의 합계 점수로 섞지 않고 나란히 표시한다.
- judge는 점수와 함께 반드시 `reason`을 남긴다.
- 루브릭 문서 자체를 judge 입력에 그대로 넣더라도, 골든셋의 예시 `suggestion` 문장을 정답 문자열처럼 비교하지 않는다.

## Judge 출력 형식

```json
{
  "runId": "...",
  "caseId": "...",
  "model": "...",
  "recipe": "...",
  "item": "group-1",
  "scores": {
    "semantic_cohesion": 4,
    "noise_exclusion": 5,
    "measurability": 3,
    "clarity": 4,
    "time_fit": 3,
    "relevance": null,
    "grammar": 5,
    "vocabulary": 4,
    "tone": 4
  },
  "notApplicable": ["relevance"],
  "reasons": {
    "semantic_cohesion": "모든 할 일이 같은 릴리스 준비 결과로 이어진다."
  },
  "judge": "codex",
  "rubricVersion": "v1"
}
```
