# 성취탭 AI 추천 골든셋

주간 목표 추천이 **의미 있는 묶음을 만드는가**를 채점하기 위한 케이스 모음이다.
관련 배경: `docs/5. 운영/프로젝트 운영/12. 기술 문서/Architecture/성취탭/ai-suggestion-quality-evaluation.md`

## 왜 필요한가

프롬프트를 고쳤을 때 좋아졌는지 나빠졌는지 판단할 기준이 없으면, 모든 튜닝이 추측이 된다.
골든셋은 그 기준이다. **정답을 사람이 미리 라벨링해 두고**, 모델 결과를 그것과 대조한다.

> ⚠️ **골든셋 케이스를 프롬프트의 few-shot 예시로 쓰지 말 것.**
> 정답을 보여준 문제로는 실력을 잴 수 없다.

## 폴더 구조

```
cases/
  weekly/          할일 → 주간 목표
    common/        페르소나를 안 타는 공통 상황
    developer/
    jobseeker/
  monthly/         주간 목표 → 월간 목표 (아직 없음)
```

**주간과 월간은 입력이 다르다.** 주간은 할일(`memos`)을 받고, 월간은 `MonthlyGoalTask` 가
**주간 목표**(`title`·`rule`·진행률…)를 받아 `goalIDs` 를 뱉는다. 그래서 `monthly/` 케이스에는
`memos` 키가 아예 없고 `weeklyGoals` 가 그 자리를 대신한다. 파일 모양이 달라 로더도 따로다.

## 케이스 형식 (weekly)

`cases/weekly/**/*.json` 파일 하나가 케이스 하나다.

```json
{
  "caseName": "운동 3개 + 무관한 잡무 2개",
  "note": "가장 기본적인 묶음. 이것도 못 묶으면 다른 케이스는 볼 필요 없다.",
  "referenceDate": "2026-07-31",
  "memos": [
    { "id": "m1", "content": "아침 러닝 30분", "icon": "🏃", "startDate": "2026-07-28 07:00" },
    { "id": "m2", "content": "헬스장 3개월 등록하기", "icon": "🏃", "deadline": "2026-07-29 20:00" },
    { "id": "m3", "content": "스트레칭 루틴 찾아보기", "icon": "🏃" },
    { "id": "m4", "content": "전기요금 납부", "icon": "💰", "deadline": "2026-07-30 23:59" },
    { "id": "m5", "content": "도서관 책 반납", "icon": "📚",
      "startDate": "2026-07-31 10:00", "deadline": "2026-07-31 18:00" }
  ],
  "expectedGroups": [
    { "type": "weekly_goal", "title": "운동 습관 만들기 시작", "memos": ["m1", "m2", "m3"] }
  ],
  "traps": [
    { "why": "둘 다 잡무일 뿐 하나의 결과로 이어지지 않는다", "groups": [["m4", "m5"]] }
  ]
}
```

### 날짜 — `startDate` 와 `deadline` 둘뿐이다

앱에는 `date` 라는 저작 필드가 없다. `AchievementDataBuilder.memoDate` 가
`deadline ?? startDate ?? updatedAt` 로 **파생시킨다.** 골든셋만 갖고 있던 가짜 필드였고,
`WeeklyGoalTask.prompt` 는 그 값을 한 번도 읽지 않아 **아무 데도 안 닿았다.**

**넷 다 나와야 한다** — 실제 할일이 그렇기 때문이다.

| 모양 | 뜻 |
| --- | --- |
| 둘 다 | 시작과 마감이 있는 계획된 일 |
| `deadline` 만 | 언제 시작하든 그때까지는 끝내야 하는 일 |
| `startDate` 만 | 그때 시작하지만 끝이 안 정해진 일 |
| 둘 다 없음 | «언제든» 할일. **주 판정에서 제외된다** |

`YYYY-MM-DD` 또는 `YYYY-MM-DD HH:mm`. 시간을 쓰는 이유는 같은 날 14시 시작과 18시 마감이
하루짜리 계획이 아니라 그날 안에서 이어지는 실행이기 때문이다.

### `referenceDate` — 이 케이스에서 «오늘»

**«이번 주» 가 어디인지 정하는 값**이다. 없으면 케이스가 시간에 따라 뜻이 달라진다 —
어제는 이번 주였던 할일이 다음 달에 돌리면 지난 주가 된다.
둘 다 날짜가 없는 할일의 파생 날짜도 이 값으로 채운다.

### `expectedGroups` — 무슨 목표인지 적는다

예전에는 `[["m1","m2"]]` 였다. 그래서 **주간인지 월간인지 구분되지 않았고**, 묶어 놓고
그게 무슨 목표인지도 안 적혀 있었다.

| 키 | 뜻 |
| --- | --- |
| `type` | `weekly_goal` / `monthly_goal` |
| `title` | 사람이 붙인 목표 제목 |
| `memos` | 묶여야 하는 id 들 |

`title` 은 **묶음 채점에 안 쓴다.** 제목 품질은 쌍 단위로 잴 수 있는 것이 아니라 별도 판정자가
볼 몫이다. 그래도 적는 이유는 **제목이 안 붙는 묶음은 애초에 묶음이 아니기** 때문이다
(→ 라벨링 가이드). 제목을 못 쓰겠으면 그 묶음을 지워야 한다는 신호다.

### 주간 목표는 한 주를 넘지 않는다

서로 다른 주에 걸린 할일을 한 주간 목표로 묶으면, **이번 주에 끝낼 수 없는 것을 이번 주
목표라고 부르는** 셈이 된다. 주는 월요일에 시작한다(앱의 `Constants` 달력이 `firstWeekday = 2`).

날짜가 하나도 없는 할일은 **면제**다 — 언제든 할 수 있으니 주를 넘길 수가 없다.

`GoldenSetSchemaTests` 가 이 규칙을 기계로 검사한다. 월간도 같은 자리에서 «같은 달» 로 본다.

### `traps` — 함정

«묶이면 안 되는 **모든** 쌍» 을 나열하지 않는다. 그러면 조합이 폭발한다 —
3개짜리 묶음 둘이 합쳐지는 걸 막으려면 9쌍인데, 그러면 **무엇이 진짜 함정인지 묻힌다.**
그 케이스가 겨냥한 것만 골라 적는다.

| `groups` | 뜻 |
| --- | --- |
| **1개** | 이 안의 항목들이 **서로** 묶이면 안 된다 (예: 같은 앱을 쓸 뿐인 할일 셋) |
| **2개 이상** | 이 묶음들이 **합쳐지면** 안 된다. 묶음 **안**은 판단하지 않는다 |

`why` 는 생략할 수 있지만 **적는 것이 좋다.** 없으면 나중에 «왜 이걸 적었지» 가 된다.

#### 정답으로 이미 표현되는 것은 적지 않는다

`expectedGroups` 가 `[A, B]` 라는 건 그 자체로 «A 와 B 는 별개» 라는 뜻이다.
그걸 `traps` 에 또 적으면 같은 말을 두 번 하는 것이고, 정답 묶음이 여럿인 케이스마다 붙는
**상투구**가 되어 «골라 적는다» 는 뜻이 사라진다.

두 정답 묶음이 합쳐지면 precision 이 이미 세게 깎인다
(3개짜리 둘을 뭉치면 예측 15쌍 중 정답이 6쌍 → F1 0.57).

**적을 것은 정답만으로 표현되지 않는 것이다.**

| 적는다 | 적지 않는다 |
| --- | --- |
| 정답 밖 항목이 정답 묶음에 **끼어드는** 것 | 정답 묶음 A 와 B 의 분리 |
| 정답 밖 항목들끼리 묶이는 것 | |
| 같은 도구·카테고리를 쓸 뿐인 것들 | |

#### 한 묶음으로 적을 때 조심할 것

`groups` 가 하나면 **그 안의 모든 쌍**이 금지된다. 정답 쌍이 섞이지 않게 해야 한다.

```json
// ✗ m4·m5·m6 이 정답 묶음인데 그 안의 쌍까지 금지된다
{ "groups": [["m4", "m5", "m6", "m7"]] }

// ✓ m7 이 그 묶음에 붙는 것만 금지한다
{ "groups": [["m4", "m5", "m6"], ["m7"]] }
```

### 필드

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `caseName` | ✅ | 사람이 읽을 이름. 무엇을 시험하는 케이스인지 드러나게 |
| `datasetType` | ✅ | 골든셋 구성 비율을 집계할 유형: `general`, `context_dependent`, `insufficient_information`, `non_goal_or_noise` |
| `successConditions` | ✅ | 이 케이스가 검증하는 성공 조건의 배열. 집계용 고정 식별자를 사용한다 |
| `note` | — | 이 케이스를 넣은 이유. 나중의 나에게 남기는 메모 |
| `referenceDate` | ✅ | 이 케이스에서 «오늘». `YYYY-MM-DD` |
| `memos[].id` | ✅ | `m1`, `m2`… 짧은 식별자. 실행 시 결정적 UUID로 변환된다 |
| `memos[].content` | ✅ | 할 일 본문 |
| `memos[].icon` | — | 이모지. 생략하면 기본값 |
| `memos[].startDate` | — | 있을 때만. `YYYY-MM-DD` 또는 `YYYY-MM-DD HH:mm` |
| `memos[].deadline` | — | 있을 때만. 같은 형식 |
| `expectedGroups` | ✅ | `{ type, title, memos }` 의 배열. 없으면 `[]` |
| `traps` | — | **특히 틀리기 쉬운 자리.** 아래 참고 |

### `expectedGroups`가 비어 있어도 된다

"묶을 게 없는 입력"도 중요한 케이스다. 모델이 억지로 묶는지 보는 시험이다.

## 라벨링 가이드

**기준은 하나다 — "이 할 일들을 다 끝내면 하나의 결과나 진전이 생기는가?"**

| 묶는다 | 묶지 않는다 |
| --- | --- |
| 목적이 같거나 하나의 결과물로 이어짐 | 같은 앱·도구·태그를 쓸 뿐 |
| 끝내면 눈에 보이는 진전이 있음 | 우연히 비슷한 시기에 등록됨 |
| 사람이 봐도 "이건 한 목표다" | 카테고리만 같음 (예: 둘 다 "공부") |

라벨링할 때 스스로에게 물을 것:

- 이 묶음에 **제목을 붙일 수 있나?** 못 붙이면 묶음이 아니다.
- 붙인 제목이 **도구 이름**(예: "Obsidian 정리")이면 잘못된 묶음이다.
- 애매하면 **묶지 않는다.** 과소 묶음이 과대 묶음보다 낫다.

## 개인정보 — 반드시 각색할 것

이 파일들은 저장소에 커밋된다. **실제 메모를 그대로 넣지 말 것.**

- 사람 이름, 회사명, 계좌·주소·연락처 → 삭제하거나 가상의 것으로
- 고유한 사건·프로젝트명 → 일반적인 표현으로
- **의미 구조만 유지하면 평가에는 지장이 없다** (예: "○○사 면접 준비" → "면접 준비")

## 케이스를 몇 개 만들까

20~30개를 목표로 하되, **처음부터 다 채우지 않아도 된다.** 아래 유형을 골고루 섞는다.

| 유형 | 왜 필요한가 |
| --- | --- |
| 명확한 묶음 1개 + 잡음 | 기본 동작 |
| 서로 다른 묶음 2~3개 | 나눠서 제안하는가 (현재 약한 부분) |
| 묶을 게 없음 | 억지로 묶는가 |
| 도구 이름만 겹침 | 표면 키워드로 묶는가 (알려진 실패 유형) |
| 메모가 아주 많음 | 프롬프트 예산 안에서 고르는가 |
| 메모 본문이 매우 긺 | 예산 컷이 제대로 도는가 |
| 여러 주에 걸침 | 주 경계를 지키는가 |
| 날짜가 아예 없음 | 날짜 없이도 목적으로 묶는가 |

## 채점 방법

`expectedGroups`와 모델 결과를 **쌍(pair) 단위**로 비교한다.

- 정답 쌍: `expectedGroups`의 각 묶음에서 나올 수 있는 모든 2개 조합
- 예측 쌍: 모델이 낸 각 목표에서 나올 수 있는 모든 2개 조합
- **precision** = 맞은 쌍 / 예측 쌍
- **recall** = 맞은 쌍 / 정답 쌍

묶음 단위로 채점하면 부분 정답(3개 중 2개만 맞춤)이 0점이 되어 개선이 안 보인다.

### 함정 감점

```
묶음 일치도 = F1 × (1 − 밟은 함정 쌍 / 전체 함정 쌍)
```

함정 쌍은 정답이 아니므로 **precision 을 이미 한 번 깎는다.** 거기 더해 곱하는 이유는
**함정이 보통 실수보다 무겁기** 때문이다 — 그 케이스가 존재하는 이유가 그 함정이다.
함정을 전부 밟으면 묶음을 아무리 잘해도 0 이 된다.

기록에는 셋이 남는다.

| 키 | 뜻 |
| --- | --- |
| `pairF1` | 순수 F1. **감점 전** 값이라 옛 기록과 그대로 비교된다 |
| `trapAvoidance` | 함정 회피율. 함정을 안 적은 케이스는 `1.0` |
| `groupingScore` | **묶음 일치도** — 최종 점수 |

함정을 안 적은 케이스는 회피율이 `1.0` 이라 **예전과 똑같이 채점된다.**
